# Правила для бэкенда

## Структура

В этом каталоге находится HTTP-сервис на Go. Файл `cmd/server/main.go` служит точкой входа и сейчас регистрирует обработчик корневого пути. По мере развития сервиса выносите повторно используемый код в отдельные пакеты этого модуля, а код запуска оставляйте в `cmd/server/`.

## Разработка и проверка

В модуле указана версия Go 1.25. Выполняйте команды из этого каталога:

- `go run ./cmd/server` — запустить сервер на `http://localhost:8080`.
- `go test ./...` — запустить тесты всех пакетов.
- `go build ./cmd/server` — проверить сборку сервера.

## Документация API (Swaggo)

- Для каждого нового HTTP-маршрута добавляйте аннотации Swaggo рядом с обработчиком: назначение, тег, метод и путь (`@Router`), параметры (`@Param`), форматы запросов и ответов, успешные ответы, ошибки и требования авторизации (`@Security`), если они применимы.
- При изменении пути, метода, параметров, схем запросов и ответов, кодов статуса или авторизации обновляйте соответствующие аннотации и модели. При удалении маршрута удаляйте его аннотации.
- После добавления, изменения или удаления маршрутов и изменения аннотаций запускайте из `backend/` команду `go generate ./cmd/server`, затем `.\generate-redoc.cmd` для обновления `docs/redoc.html` из контракта. Включайте обновлённые файлы в `backend/docs/` в то же изменение; не редактируйте сгенерированные контракты и HTML вручную.
- Если изменение затрагивает преобразование Swagger 2.0 в OpenAPI 3.0 (например, форматы обновления профиля), актуализируйте также `cmd/openapi`.
- После перегенерации выполняйте `go test ./...` и `go build ./cmd/server`, проверяйте соответствие `docs/openapi.json` фактическому поведению API.

## Стиль кода и тесты

Форматируйте изменённые файлы Go с помощью `gofmt`. Используйте имена пакетов в нижнем регистре и короткие, понятные идентификаторы. Размещайте тесты рядом с проверяемым кодом в файлах `*_test.go`, называйте тестовые функции `Test...`. Сейчас тестов и порога покрытия нет; добавляйте предметные тесты для новых обработчиков и бизнес-логики и выполняйте `go test ./...` перед отправкой изменений.
