# Чек-лист ревью

Пройди все разделы и определи применимость по diff и зависимым сценариям. Проверяй пункты внутри применимых разделов. «Проверено» означает, что код или проверка дают основание для вывода; отсутствие файла в diff не делает раздел автоматически неприменимым. Квоты замечаний нет.

## 1. Область и намерение

- [ ] Известны база, head или состав локальных изменений; staged и untracked учтены согласно запросу.
- [ ] Прочитан полный diff, включая удаления, переименования и новые файлы; контекст взят из проверяемого снимка.
- [ ] Понятны цель изменения, ожидаемый результат и совместимость; планы не приняты за уже реализованные требования.
- [ ] Найденные дефекты внесены diff; существующие проблемы не приписаны автору.

## 2. Архитектура

- [ ] Проверены применимые правила A1–A8 из [architecture.md](architecture.md), включая зависимости через относительные импорты, реэкспорты и динамическую загрузку.
- [ ] Новая логика находится в соответствующей области; изменение не создаёт второй независимый механизм сессии, API-клиент или состояние профиля.
- [ ] Сохранились границы server/client и доверия браузер → сервер → БД. Разделение обязанностей не подменено требованиями внедрить несуществующие service/repository слои.
- [ ] Архитектурный переход, если он намеренный, согласован с потребителями и инструкциями; текущие компромиссы не объявлены новыми дефектами.

## 3. Backend и данные

- [ ] Маршрут доступен с ожидаемыми методом, путём и middleware; неподдерживаемые методы обрабатываются корректно.
- [ ] Ввод валидируется сервером: типы, границы, размер, лишние поля/объекты; отказ не оставляет частичную запись.
- [ ] Чтение и изменение данных ограничены текущим владельцем; ID владельца не доверяется из тела запроса.
- [ ] Ошибки GORM обработаны; контекст запроса передаётся в операции БД; транзакции и ограничения выдерживают конкурентные запросы.
- [ ] Изменения модели/AutoMigrate совместимы с существующими данными, значениями по умолчанию, индексами и связями.
- [ ] Для изменённых goroutine, файлов и сетевых вызовов проверены завершение, освобождение ресурсов, отмена и таймауты.

## 4. Frontend и UX

- [ ] Loading, empty, success и error состояния доступны; ошибка позволяет повторить действие без потери введённых данных.
- [ ] Двойная отправка и гонки ответов не приводят к дубликатам или устаревшему UI; эффекты корректно завершаются при уходе со страницы.
- [ ] Успешная мутация обновляет список/профиль и зависимые компоненты; данные не смешиваются между пользователями.
- [ ] Формы согласованы с серверной валидацией; ошибки авторизации отличаются от временной сетевой ошибки.
- [ ] Изменённые кнопки, поля и диалоги доступны с клавиатуры, имеют подписи, корректные disabled/focus и сообщения ошибок; мобильный сценарий сохранён.
- [ ] Использованные Next.js API проверены по установленной версии и локальной документации, без предположений по памяти.

## 5. Общий API и документация

- [ ] UI → клиент → маршрут → обработчик → ответ согласованы по пути, методу и авторизации.
- [ ] JSON-поля, типы, optional/null, пустой массив, даты и единицы измерения одинаково понимаются обеими сторонами.
- [ ] Клиент корректно обрабатывает успешные статусы, включая 204 без JSON, и ошибки `error.code`/`error.message`.
- [ ] Swaggo и OpenAPI описывают реальное поведение изменённых операций; при изменении преобразования учтён `backend/cmd/openapi/`.
- [ ] Изменение контракта проверено с обеих сторон, даже если одна сторона не менялась; производные Swagger/ReDoc соответствуют источнику.

## 6. Сессия и безопасность

- [ ] Access JWT и refresh cookie не перемещены в небезопасное хранилище; cookie сохраняет нужные HttpOnly/SameSite/Secure/path.
- [ ] CORS/Origin и `credentials` совместимы, защита cookie-операций сохранена.
- [ ] Ротация refresh атомарна, конкурентные клиенты не ломают сессию, повтор авторизованного запроса ограничен; logout отзывает сессию.
- [ ] Данные пользователей изолированы; секреты и внутренние ошибки не попадают в ответы, логи и клиентский bundle.
- [ ] Для аватаров проверены размер, содержимое, декодирование, безопасный путь, очистка старого файла после сохранения и согласованность файла/БД.
- [ ] Для добавленных сетевых запросов к пользовательским URL проверены SSRF и перенаправления. Само сохранение URL не означает сетевого запроса.

## 7. Конфигурация, зависимости и запуск

- [ ] Переменные окружения, `.env.example`, Compose и скрипты запуска согласованы; локальные секреты не добавлены.
- [ ] Изменения зависимостей согласованы с lock-файлом и версиями runtime; клиентские зависимости не требуют серверных секретов.
- [ ] Новые настройки имеют понятное поведение по умолчанию или явную ошибку запуска; сохранность БД и uploads не нарушена.

## 8. Проверки и отчёт

- [ ] Статический скрипт запущен для правильного снимка; нарушения подтверждены, пропуски не выданы за успех.
- [ ] Проверки из применимых AGENTS выполнены или указан конкретный блокер; для общего API охвачены обе части.
- [ ] Тесты проверяют изменённое поведение и отказ/границы; отсутствие теста само по себе не выдано за баг.
- [ ] Интеграционные тесты используют только тестовую БД; учтены skipped-тесты и ограничения браузерных моков API.
- [ ] Каждое замечание содержит приоритет, место в diff, условие и последствие; итог включает покрытие разделов и реальные результаты команд.
