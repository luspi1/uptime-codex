## Запросы на включение изменений

При просьбе создать PR выполняйте следующий порядок действий. Если разработчик явно указал текущую ветку, используйте её без создания и переключения веток.

1. Проверьте `git status`, текущую ветку и `origin`. Не включайте посторонние локальные изменения. Обновите ссылки через `git fetch origin` и проверьте наличие открытого PR для этой ветки через `gh pr list --head <branch> --base main --state open`.
2. Изучите все коммиты и итоговый diff относительно актуальной целевой ветки: `git log origin/main..HEAD`, `git diff --stat origin/main...HEAD` и `git diff origin/main...HEAD`. Описание должно отражать весь итоговый результат ветки.
3. Выполните проверки из `AGENTS.md` затронутых частей приложения и дополнительные проверки, необходимые для изменений. Для общего API проверьте обе части. Укажите реальные результаты; отдельно отметьте пропущенные проверки, ограничения окружения и необходимость внешних сервисов.
4. Подготовьте заголовок по Conventional Commits: `<type>[optional scope]: <description>`. Используйте типы из раздела [«Коммиты»](git.md#коммиты), английский язык, повелительное наклонение и длину до 72 символов. Выбирайте тип по основному результату изменений, например `feat: add website monitoring point creation`.
5. Подготовьте подробное описание на русском языке: решаемая задача и итоговое поведение; изменения фронтенда, бэкенда и документации; контракт API с форматами запросов, ответов и ошибок при его изменении; проверки с командами и результатами; ограничения и действия для запуска. Добавляйте ссылки на связанные задачи, если они известны, и снимки экрана при изменениях интерфейса. Не выдумывайте ссылки и результаты; если снимки приложить не удалось, укажите это явно.
6. Сохраните точный текст описания в UTF-8 во временный файл вне отслеживаемых файлов репозитория. Используйте `--body-file`, чтобы сохранить переносы строк и избежать интерпретации текста оболочкой.
7. Если для PR нужны дополнительные изменения, сначала подготовьте и проверьте их. Коммиты выполняйте после согласования с разработчиком согласно разделу [«GitHub Flow»](git.md#github-flow). Отправьте согласованные коммиты текущей ветки через `git push -u origin <branch>`; не переписывайте историю через force push.
8. Создайте PR командой `gh pr create --base main --head <branch> --title <title> --body-file <file>`. Если открытый PR уже существует, обновите его заголовок и описание через `gh pr edit <number> --title <title> --body-file <file>` вместо создания дубликата.
9. Проверьте результат через `gh pr view <number> --json url,title,baseRefName,headRefName,body` и сообщите разработчику ссылку на PR, результаты проверок и существенные ограничения. Создание PR не означает разрешение на его слияние или удаление ветки: эти действия согласовывайте отдельно.
