# Регистрация и авторизация на backend с GORM

## Кратко

Использовать [GORM с драйвером PostgreSQL](https://gorm.io/docs/connecting_to_the_database.html) для пользователей и refresh-сессий. Первую схему создавать при запуске сервера через [AutoMigrate](https://gorm.io/docs/migration.html).

## Реализация и контракт API

- Описать модели пользователя и refresh-сессии в GORM. Сделать email уникальным; пароли хранить как bcrypt-хеши, refresh-токены — только как хеши.
- Добавить `POST /api/auth/register` и `POST /api/auth/login` с телом `{"email":"…","password":"…"}`. Регистрация сразу создаёт сессию. Ответ содержит пользователя, access JWT и срок его действия; refresh-токен устанавливается в HTTP-only cookie.
- Добавить `POST /api/auth/refresh`: в транзакции GORM заменять refresh-токен и возвращать новый access JWT. Повторное использование старого токена отклонять. `POST /api/auth/logout` отзывает текущую сессию и очищает cookie.
- Добавить `GET /api/auth/me`: проверять access JWT из `Authorization: Bearer` и возвращать ID и email пользователя.
- Использовать единый JSON-формат ошибок: некорректный ввод — 400, занятый email — 409, неверные учётные данные или токен — 401.

## Проверка

- Выполнить `go build ./cmd/server`.
- Вручную проверить создание таблиц, регистрацию, вход, доступ к `/me`, обновление токенов, отклонение старого refresh-токена и выход. Автоматические тесты не добавлять и не запускать.

## Принятые настройки

- Срок access JWT — 15 минут, refresh-сессии — 30 дней. Refresh-токен — криптографически случайная строка, не JWT.
- Cookie: `HttpOnly`, `SameSite=Lax`, путь `/api/auth`; `Secure` включается настройкой для HTTPS. Локальный разрешённый origin — `http://localhost:3000`.
- Адрес PostgreSQL, секрет JWT, разрешённый origin и режим `Secure` задаются переменными окружения и документируются в `.env.example` и README.
- Подтверждение email и восстановление пароля в эту версию не входят.
